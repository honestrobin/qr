# QR 1.4.0, 11 October 2026

## What changed

- **QR counts what's done on the page, never what's in it** (the maintainer's decision the same
  day, and the Code's article 5 as changed in robinscode #22): a code made, a code taken and how,
  a suggested fix taken, a code that doesn't scan, Keep it plain turned on. Each count has the
  page's language and a random id made for that page view, which the page keeps nowhere.
- **The counts go to the page's own address** (`/count`), where QR's first piece of server code
  (`worker/index.js`) refuses anything not on its list and writes the rest to Cloudflare's own
  store (Workers Analytics Engine, dataset `qr_counts`), one row per count, with nothing of the
  visitor's. Cloudflare keeps the rows three months. The server code sends nothing anywhere else.
- **About 60 counts a minute from one address** are kept, so nobody can flood the store.
  Cloudflare's limiter uses the address only to apply the limit, and is approximate; the address
  is never part of a row. The Worker's logs are off, so Cloudflare keeps no log of the count
  requests for us.
- A share or a copy is counted once it has happened, not when its button is pressed. A sheet is
  counted when it's sent to print.
- **A file that wasn't ours to serve is gone:** a copy of fonttools, a Python package used once to
  cut the fonts, went in by mistake with 1.2.0 and was downloadable at qr.honestrobin.com until
  this release. It held nothing private.
- No new company: Cloudflare already served the page and counted visits.

## Promises this release touches

| Promise | How | Ledger |
|---|---|---|
| By default we count visits, and what's done on a page | New: the list, pinned by a test, and the server code that keeps to it | Tested |
| The counts are kept with nothing of yours | New: one row of listed values, nothing sent elsewhere, a limit per address, no logs | Tested |
| Every company that touches your data is listed | Cloudflare now also runs the server code and keeps the counts | Tested |
| A copy elsewhere sends us nothing | A copy's server code writes to its own deployer's store; run locally, the store keeps nothing | Tested |
| Two things kept on your device | Reworded: the counts carry the page's language and say when Keep it plain is turned on | Built, no test |
| Run it yourself | The page is still plain files; the server code only stores counts, and a copy works the same without it (a new test) | Tested |

**A guard changed:** the privacy test that reads every request used to refuse any request but a
GET to the page's own address; it now also lets through a POST to `/count`, but only when its
body is exactly one of the listed counts, and it fails unless the counts were sent and read.

**Not announced 30 days ahead.** The Code says a change that removes or weakens a protection is
announced at least 30 days before it applies. Counting what's done on a page is new, and wasn't
announced ahead: the Code isn't binding yet, QR has no accounts to tell, and the changelog says it
the day it ships.

## What the maintainer read

He decided that counts which don't identify anyone are fine to keep, and approved the wording of the Code and the rule. Told what the promise review found
(below), he chose Cloudflare's own store over PostHog and Plausible.

## What agents checked

- **A second agent's promise review** of the first version, which passed counts on to PostHog,
  found that the checks' own runs had sent their counts to the maintainer's real PostHog project:
  the key was in `wrangler.jsonc`, and wrangler's local server answers as qr.honestrobin.com, so
  the check meant to stop it didn't. 326 test counts reached PostHog from GitHub's machines,
  10:52 to 10:57 UTC, nothing from any person; the key was taken out at once, and that version
  never went live. It also found that what Cloudflare adds when a Worker calls another company
  hadn't been checked. Both are why the counts stay with Cloudflare now: nothing is passed on, no
  key exists, and wrangler's local store is a stand-in that keeps nothing and takes no setting to
  reach the real one (read in miniflare 5.20261001.0-alpha and wrangler 4.147.0's config schema).
- Its other findings are in: a count's name must be text, a test pins the list, the limit per
  address, and clearer words in the ledger and README.
- **A second promise review of this version** found no broken promise, and asked for: the Worker's
  logs turned off explicitly (Cloudflare turns them on by default for new Workers, and they'd hold
  each request's details); the limit described as approximate, as Cloudflare's docs say; the
  whole of Cloudflare's settings pinned by a test; a share or copy counted only once it happens;
  and a test that the page works without the server code. All are in.
- **The checks** passed on the merged version (c0b2558): 239 tests in three browsers. Getting
  there found two things. Every test runs from the same machine, so the limit per address
  refused the checks' own counts: requests from the machine itself, which only happen when QR
  runs locally, aren't limited, and a test says so. And in the checks, Chrome reported each count
  as a failed request, because the page never read the empty answer: it reads it now. That one
  was reproduced on the maintainer's Raspberry Pi before the fix.
- **The deploy** stopped once, because Analytics Engine has to be switched on in Cloudflare's
  dashboard before a Worker can write to it. The maintainer switched it on, and the deploy ran
  again from the same commit: 238 passed, and one test that times the code's redraw on an
  iPhone passed on its second try, as it often does.
- **Live, after the deploy:** the page loads the new `qr.js`; `/count` refuses a GET (405), a
  count not on the list (400) and an oversized one (413); the fonttools file is gone (404).
  Cloudflare's settings for the Worker show the store `qr_counts`, the limiter, no log push, and
  no log setting at all.

## What nobody checked

- That Cloudflare stores the rows as written, and that the limit per address holds on our
  account's plan, before the first real counts arrive.
- That Analytics Engine adds nothing to a row but its time and sampling columns: from its docs,
  to be checked on the first real row.
- That the Worker keeps no logs: Cloudflare shows no log setting for it, which we read as off,
  but our key can't read the log store to confirm. That's a guess until someone looks.
- A real phone: the maintainer's own test comes next.
