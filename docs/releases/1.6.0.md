# QR 1.6.0, 12 October 2026

## What changed

- **Print a sheet picks a layout, not a size:** "How many on a page" with four small pictures of
  the page: 1, 4, 12 or 30. Each code is then 18, 8.5, 5 or 2.5 cm wide, a little less with a
  caption. The maintainer asked for this after testing 1.5.1: instead of a size in centimetres,
  pick the layout, the way label printers do.
- **A sheet no longer prints at the size chosen for the files.** Since 1.3.0 a sheet held as
  many codes as fit at that size. Nobody had printed a sheet yet: the counts since 1.4.0 hold two
  codes made, one fix taken and one copy, and no sheet.
- **A layout that would print the code smaller than it scans is greyed out,** and a line says
  why. If the chosen one becomes too small (a longer link makes a denser code), the choice moves
  to the nearest layout with fewer, bigger codes.
- **A caption gets the room it needs:** it's measured at the code's width in the sheet's own
  font, and the codes shrink until code and caption fit their row. A first draft used a fixed
  allowance, and a 60-character caption pushed 12 and 30 onto a second page.
- **The files' print size is one line under the buttons** ("Downloads print 5 cm wide."), with
  "At least … cm, so phones can read it" under it, and Change opens the same − / + as before.
  The ruler under the code is gone.
- **The line under the headline starts with "Free as free gets: no sign-up."** The maintainer's
  wording, asked for the same night; in the other languages, translated by meaning ("as free as it
  can be"). Ledger row 22 already promises no account.
- **Counts:** a sheet's count no longer carries a size. Its size follows from how many are on
  it, and with captions measured, a size would have hinted at how long the caption is. `codes`
  is now 1, 4, 12 or 30.

## Promises this release touches

| Promise | How | Ledger |
|---|---|---|
| The PNG and the SVG carry the print size; never smaller than the code scans; a sheet on one page | Files: as before, set behind Change. Sheet: layouts, greyed when too small, one page with any caption | Tested |

| A feature you use isn't removed without notice | A sheet at a chosen size goes. Per the rule since robinscode #23, a notice period doesn't hold up a change the maintainer asks for before a product has users; the changelog says it | By hand |

**Guards changed:** row 55's two tests were rewritten for the new screen, and none was weakened:
the files' print size, the PNG's and the SVG's size and the 2 cm floor are checked as before,
behind Change. A third test is new: every layout prints on one page of A4 and of Letter, as a
PDF with the sheet's 1 cm margins, with no caption, a short one, a 60-character one and one
without spaces. It also checks which layouts are greyed out for each.

## What the maintainer read

He picked option A from four mockups (today, A: pick a layout, B: what it's for, C: count, not
cm), and asked to keep choosing the files' size as well, without it being
overwhelming. He saw that version mocked up, and screenshots of the built one. He then
asked to say on the page that there's no sign-up, suggested "Free as free gets", and picked that
wording over a plain one. Asked whether two sizes (the downloads' and the sheet's) were now confusing,
he chose to name the line "Downloads print … cm wide", so it reads as the downloads' and not the
sheet's, and to judge on his phone whether four sheet sizes are enough.

## What agents checked

- **On the maintainer's Raspberry Pi, in Chromium, against the local pages:**
  - the size line and Change;
  - every layout's size, with and without a caption;
  - a dense code greying out 30;
  - one page per sheet for every layout on A4 and Letter, with English, German and Japanese
    captions.
- **A translation check** back-translated the new lines in all 12 languages. Its findings are in:
  - "Fits A4 and Letter" had no subject, and read as "each code fits on A4" in Polish and
    Croatian. Now: "Each code is … cm wide, on A4 or Letter paper."
  - "The greyed-out ones would be too small" meant the code, not the layouts.
  - Korean's new lines were formal where the rest of the page is friendly.
  - Two stiff lines in Polish and Croatian, and three Japanese wordings.
  - Japanese no longer gets a space after 。.
  - Change is described by the size line for screen readers.
- **A promise review** found nothing broken, and its findings are in:
  - The "At least … cm" line had moved behind Change, so the page no longer said how small you
    can print without a tap, while the tests that guard it still passed: it's visible again,
    and the test checks that.
  - A sheet's count carried a size that depended on the caption's length; the size is gone.
  - "5 cm unless you change it" was wrong for dense codes, which start bigger.
  - The changelog now says a sheet no longer follows the files' size.
  - The print test passes the sheet's margins explicitly and checks which layouts are greyed
    out.
- **CI's first run** failed one test in all three browsers, because it read the size line with
  its hidden Change button. Fixed.

## What nobody checked

- Printing from Firefox or Safari, or with print settings a person changes (scale, margins). The
  one-page check is Chromium's PDF output only.
- That the printed code's width matches the size the page names; Chromium shrinks content that is
  too wide, and a page count can't see that.
- A real printer, and a real phone.
- The translations by a native speaker.
