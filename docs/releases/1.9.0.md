# QR 1.9.0, 15 October 2026

## What changed

- **On a phone, the code sits right under the field.** Typing put the code 720 points down an
  844-point screen, under the keyboard: the robin said it had checked 625 squares, and the code it
  checked was out of sight. On screens up to 1004 px wide, every width where the two columns stack, the parts now stack
  in this order: the headline, the field, what the code opens, the code with its check, the robin
  and its line, the paragraph under the headline, then the buttons and everything else. It's a change to the
  stylesheet only; each part keeps its look, and nothing changes on a wide screen.
- **The robin's first line says what it does:** "I'm the robin. I check every code before you
  print it." It used to say it was here to lighten up your day, an idiom that said nothing the
  robin does. In every language.

## Promises this release touches

None changes. The robin's line is a fact about what the page does: it reads every code back with
a QR reader before it says "Scans fine", as the ledger's "Checked before you print it" row says.
The guard test "the robin says who it is and counts each code's squares, and stays" keeps every
check it made and names the new line; on a narrow screen it expects the robin under the code
instead of above the field, which is where the robin now stands there.

## What the maintainer read

He picked this layout from two options on the 15 October review page, from a picture of the live
page with its parts moved ("For the QR I'll go with your recommendation"), and the new line with
it. He hasn't seen the built page or read the translations.

## What agents checked

- **The layout,** on the Pi with headless Chromium, as an iPhone 13 and as a 1366 px laptop,
  before the pull request: the code's top edge moved from 720 to 408 points on the phone, nothing
  moved on the laptop, and the page still made and checked codes.
- **The translations:** written by Claude, then checked by a second agent translating all twelve
  back into English. It corrected four: Croatian (the verb's aspect said "I'll check" instead of
  "I check"), Japanese and Korean (who prints was left to be guessed) and Turkish (the same).
- **The promise reviewer** read the change against the ledger: nothing breaks a promise, the
  guard test keeps every check it made, and no ledger row changes. On its reading: the changelog
  line says what sits between the field and the code; the stacked order's breakpoint moved from
  960 to 1004 px, so it covers every width where the columns stack; and the ledger's "Where our
  words are ahead of the code" now says that the download buttons go live a quarter second before
  the check has read the code back, which the robin's line doesn't say.
- **The checks** in desktop Chrome, Chrome on Android and Safari on iPhone passed on the pull
  request (run 38789829496 on the first commit, then the run on the final one), and the deploy
  workflow runs them again before it deploys.

## What nobody checked

- A real phone with a real keyboard; the keyboard's height was drawn in from a typical one.
- A tablet between 480 and 1004 px wide, which gets the stacked order too; and a check answer
  longer than one line, which on a narrow screen moves the robin down a little.
- The new line in the eleven languages nobody here reads, beyond the back-translation.
- A screen reader: on a narrow screen the parts are read in the page's order, not the new visual
  order.
